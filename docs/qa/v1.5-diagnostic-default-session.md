## Implemented contract

- No-subcommand invocation is a requested session, defaulting to anonymized,
  next 3 reservations, 300 seconds and no automatic browser opening.
- Optional, explicitly ignored `config/diagnostic.local.json` accepts only mode,
  next, ttlSeconds, outputDir and openReport. Strict types, existing diagnostic
  ceilings and an 8 KiB read bound apply; UTF-8 BOM is supported for PowerShell.
  Local private mode or an explicit argument is required for private capture.
  Explicit CLI mode/limits override preferences; advanced subcommands keep their
  own configuration behavior. No actual local preferences file was created/modified.
- Normal `.env` loading is quiet and does not override the environment. Help/demo
  remain independent of local secrets. The npm entry uses `node --import tsx` to
  avoid the tsx CLI child-process signal relay.
- Discovery checks the existing public manifest without Authorization before
  authenticated diagnostic status/schema/capability checks. Only explicit TCP
  refusal permits startup; foreign/denied/malformed/incompatible listeners and
  timeouts fail closed. Reusing an older bridge requires restarting it with this
  checkout's ownership-aware HTTP routes.
- Startup uses the normal validated production config/app inside the CLI process,
  with a quiet logger. It adds no recorder or background process. Its listener
  applies the normal localhost/authentication policy before additionally fencing
  starts to the foreground CLI's random in-memory owner header. This prevents a
  foreign capture from appearing on a listener scheduled for shutdown. Reused and
  normally started bridges are unaffected by that additional restriction.
- The existing capture workflow handles quota, TTL, Enter and latched signals.
  EOF is ignored. Ctrl+C/SIGTERM/delivered SIGHUP stop and export an identified
  exportable session once, including interruption during requests, then return 130.
  Export failure takes precedence over that successful-interruption exit code.
- Guided start atomically preserves an existing retained report. Optional session
  ID on stop atomically refuses an active replacement. Final report ID/privacy
  validation remains mandatory. Legacy manual start/stop bodies remain compatible.
- Default output uses a new random filename under ignored `.cache/diagnostic-reports`.
  The existing bounded, atomic, no-clobber exporter and linked-ancestor checks remain
  authoritative. Custom directories must already exist; Windows ambiguous/device,
  UNC, ADS and drive-relative syntax is rejected. There is no fallback destination.
- A reused listener stays running. Only an owned listener is closed after export
  or failure, with service cleanup stopped and a bounded HTTP draining grace period.
  Browser opening uses fixed executables and argument arrays, without a shell;
  failure leaves the report usable. No secret is placed in process arguments,
  URLs, report data or operational output.

See [usage and configuration](../diagnostics.md#one-console-local-session).

## Residual limits

- Windows X/forced termination can interrupt asynchronous cleanup. No reliable
  save is promised, and no persistence service or orphan process is introduced.
- Public manifest identity is a hint, not cryptographic proof against a hostile
  local process impersonating the bridge. The existing same-user/Bearer threat
  boundary remains; absolute malicious-local-process secret isolation is not claimed.
- Export requires local permissions and hard-link support. Known linked ancestors
  and overwrite are rejected, but the existing hostile same-user directory race
  limitation and inherited Windows ACL behavior remain.
- If export fails on an owned bridge, shutdown discards its in-memory report. On
  a reused bridge the retained report remains exportable until its original TTL.
  Correct output permissions/filesystem support before another requested capture.
- A retained report on a reused bridge blocks another guided session until normal
  expiry, even after it has been exported. This preserves the previous session.
- Closing an owned listener can drain/close its own active HTTP connections; this
  command is a bounded diagnostic run, and is not a persistent playback service.
- US-1507 presentation defects, playback correlation and other pre-existing release
  or security findings are outside this change and remain unresolved.
