## Baseline and defect

Before modification, checked branch `work/us-1501-diagnostics`, HEAD
`18267ac0975f50e201c812db02d1c43cbb2d51ce` and the full dirty/untracked status
in the existing `.worktrees/us-1501-diagnostics` checkout. All earlier uncommitted
work was retained. Inspected the script, CLI, capture workflow, local bridge/config,
interaction, session/process tests, current guide and preceding QA checkpoint.

The session's unconditional finally block closed an owned bridge immediately after
quota/TTL/Enter export. This ended the service Stremio was using. The diagnostic
capture limit must not determine the lifetime of the bridge service.

## Corrected behavior

- Quota, TTL and Enter finalize only capture. The existing `next` reservation quota
  (1..10) remains the sole resolution limit. No new resolution counter, recorder,
  capture TTL or retention extension was introduced.
- The workflow performs its one stop/export attempt and confirms capture OFF.
  A successful export prints the unique HTML path and optionally opens it through
  the existing helper. An owned bridge then remains in the foreground, serving
  normal Stremio requests. Enter or EOF after capture does not close the service.
- Existing signal listeners remain installed through foreground service lifetime
  and shutdown. Ctrl+C after export closes the owned listener without another report.
  Ctrl+C during capture attempts safe stop/export before closing. SIGTERM and
  delivered SIGHUP use the same path; repeated signals remain latched.
- A reused bridge is never closed. Its CLI returns after export (or an error), with
  the existing report retention and authorization boundaries unchanged.
- `CaptureExportFailure` identifies failures only after stop has confirmed OFF,
  including report retrieval/validation, rendering and atomic file export. The CLI
  prints the existing safe error code immediately and keeps an owned bridge alive
  for playback and possible recovery. Unsafe/uncertain capture failures retain the
  previous fail-closed cleanup behavior.
- No automatic retry, second report, fallback destination or rearmed capture occurs.
  If a valid retained report exists, an explicit advanced export can recover it
  before its original retention expires. For a non-default port, pass `--bridge`
  explicitly to that advanced command. Missing, invalid or expired reports may not
  be recoverable. A prior export failure remains the eventual exit code, including
  after manual recovery. If shutdown was already requested, the owned bridge closes
  after the failed attempt and its remaining in-memory report is discarded.
- Localhost-only, public identity check before Bearer, administrative authentication,
  ownership fencing, URL/SSRF policies, diagnostic budgets and atomic no-overwrite
  export are unchanged. The owning CLI's foreground wait does not extend capture
  or report retention. No background process or persistence was added.

The user's planned local preferences are accepted without changing defaults:

```json
{
  "mode": "anonymized",
  "next": 5,
  "ttlSeconds": 300,
  "openReport": true
}
```

`outputDir` is optional and retains its ignored default. No real preferences,
private configuration or local report was read into a fixture, created or modified.

## Regression evidence

The real script/production app runs in a separate Node process with isolated temporary
synthetic configuration and closed stdin. Its tests now check:

1. Five Stremio stream requests exhaust a `next: 5` quota, generate one valid HTML,
   leave diagnostic status OFF and keep the owned TCP listener accessible.
2. A one-second capture TTL exports zero resolutions and leaves the same service up.
3. Another ordinary Stremio stream request after export succeeds; status remains OFF
   and the retained report is unchanged.
4. Only subsequent shutdown releases the owned port; repeated handled SIGINT events
   do not create another HTML or another export message.
5. Handled SIGINT during capture saves a valid report before process exit/port release.
6. A removed output directory produces an actionable failure with service still up.
   Stremio still works, and an explicit advanced CLI export against the real listener
   recovers the retained report. Final shutdown creates no extra report.
7. Authenticated competing starts remain fenced off, even after a manual stop, and
   unauthorized starts still require the existing authentication.

Additional session/component tests cover Enter during capture, Enter/EOF after capture,
optional opening once, missing/invalid report responses, manual recovery, repeated
signals, close exactly once, and no automatic export retry. Existing reuse tests
confirm that a pre-existing listener remains active when its CLI returns.

Windows signal tests use a test-only preload/private parent-child channel to emit
handled SIGINT events; Windows `kill(SIGINT)` would terminate the child instead of
testing asynchronous handlers. No IPC/signal injection hook or configurable executable
was added to production. This validates the handler and real HTTP/process lifecycle,
not physical terminal signal delivery or a Windows X event.

## Limits and changed files

Closing a Windows window with X still does not guarantee asynchronous export/cleanup.
Use Ctrl+C and wait for orderly shutdown. Forced termination can discard an unexported
in-memory report. The existing retention limit, inherited Windows ACLs, hard-link
requirement and hostile same-user path/identity limits remain unchanged. Synthetic
HTTP continuity does not establish real media playback compatibility or resolve
US-1507 or other existing release/security findings.
