# v1.5.2 — Node 20: pérdida del deadline compuesto durante GC

**Resultado: timeout corregido y validación local PASS.** CI alojado y Linux: NOT RUN. No se autoriza publicación y no se crea ningún commit. HEAD permanece en `ae7797e41931778940d87f3a5c58b13c6df31c89`, rama `work/v1.5.2-magicast-source-map`.

## Causa confirmada

`conflictCaseSignal()` devolvía `AbortSignal.any([global, AbortSignal.timeout(ms)])` sin conservar la señal temporal. El código interno del Node 20.19.0 instalado usa WeakRef tanto en las fuentes de any como en el callback del timeout; el GC puede recoger esa fuente y cancelar su timer sin emitir abort. Node 22.23.2 retiene explícitamente las señales temporales en gcPersistentSignals.

Se reprodujo con un programa sintético fuera de Git, `--expose-gc`, doce ciclos de GC en macrotareas distintas, el resolver real con 28 providers sintéticos y concurrencia 2, y withinSmokeDeadline real. La señal observada por WeakRef es la primera, correspondiente al caso; no los timers individuales posteriores del registry. Se observa antes del deadline para no confundir colección posterior al aborto con la causa del bloqueo.

| Código/runtime | Señal recogida antes del deadline | abort | withinSmokeDeadline rechaza | resolver termina |
| --- | --- | --- | --- | --- |
| H1 sin corrección, Node 20.19.0 | Sí | No | No | No |
| H1, Node 20, control con referencia fuerte | No | Sí | Sí | Sí |
| H1 sin corrección, Node 22.23.2 | No | Sí | Sí | Sí |
| Corregido, Node 20.19.0 | No | Sí | Sí | Sí |

El programa usa un deadline sintético de 1000 ms y observa a los 1300 ms; después cancela explícitamente para limpiar. Estos valores de observación no cambian límites de aplicación ni del test original. Se contrastó además con una copia histórica cuya fuente coincide con H1 normalizando BOM/finales de línea; no se modificó esa copia. La reproducción conserva los tres estados, no solo el timeout de Vitest.

## Corrección mínima y regresión

En `scripts/qa-identity-conflict-review.ts`, la señal temporal tiene un listener propio y la señal compuesta otro, compartiendo una función de limpieza que conserva ambas referencias. Cuando aborta cualquiera, se eliminan los dos listeners. Si la cancelación global ya ocurrió, se limpian inmediatamente. Se mantiene AbortSignal.any con el mismo orden `[global, timeout]`, sus razones nativas y la precedencia de una cancelación global anterior.

No cambia withinSmokeDeadline, el timeout de 30 ms del test afectado, timeouts globales/de providers, reglas Identity, scoring, ranking, probes, proveedores o playback. No se usan retry ni skip para solucionar el bloqueo.

Se añaden cinco casos al archivo de tests existente:

- Deadline, cancelación global y global ya cancelada: razones correctas y cero listeners propios después de terminar.
- Dos subprocesos con GC forzado, timeout y cancelación global: abort, rechazo, resolver finalizado, tres providers iniciados y cola drenada. El watchdog solo registra el estado antes de limpiar; no convierte un deadline perdido en éxito.
