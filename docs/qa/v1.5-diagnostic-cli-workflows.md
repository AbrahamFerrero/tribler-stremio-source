## Implemented behavior

`npm run diagnostic -- demo` requires neither token nor bridge. A new controller
starts OFF and is explicitly started only for the requested demonstration. The
actual registry/resolver/observation adapter runs three resolutions of an invented
media item against an in-memory provider, using checked-in ranking defaults and
injected URL-policy address lookup. There is no direct probe, outbound transport,
production configuration/`.env`, HTTP listener, Tribler or real media/provider.
After synchronous recorder closure and controller stop, the real validator and
HTML renderer write one sanitized `report.html` using the safe no-clobber exporter.

Output is in a fresh random directory under `.cache/diagnostic-demo/`. Git ignore
membership is verified before directory creation; existing ancestors are checked
for symlinks/non-directories. No real data is supplied. The generated path is printed.
Only interactive non-CI sessions attempt platform default browser opening, using
fixed executable/argument arrays without a shell and a generated local file URL.
Unsupported sessions or launch failures print offline opening instructions. Browser
opening is optional; an already-written report remains usable if it fails.
Advanced commands and `capture` do not load the synthetic resolver module/defaults.

`npm run diagnostic -- capture --output PATH` requires an existing authorized local
bridge and existing BRIDGE_ADMIN_TOKEN. Output is mandatory. Defaults: 3 reservations,
300 seconds; `--next` and `--ttl` retain the existing 1..10 / 1..300 bounds. It requests
explicit in-memory retention and calls only the original administrative
start/status/stop/report API. Polling is every 500 ms, bounded by the original TTL;
it never creates a provider, stream, probe, media or playback request. Completion
means quota reservations consumed and no active captures, not universal traceability.
Enter finishes early in an interactive terminal. Expiry, overflow and concurrency
omissions retain their existing controller semantics.

SIGINT/SIGTERM is latched during in-flight requests; cleanup attempts a confirmed
owned-session stop and exits 130 without starting export. Once an explicitly
requested atomic write has begun, interruption may not prevent its safe completion.
Input newline is inspected without accumulating or retaining entered text. Listener,
timer and terminal-flow cleanup leaves other signal listeners intact and does not
leave an initially inactive stdin stream flowing. Failed export produces no fallback
file or overwrite; any sanitized server report expires on its original retention
deadline. Unknown start outcome or failed cleanup prints a fixed warning and leaves
the bounded server TTL authoritative; unidentified sessions are never blindly stopped.

Every poll/pre-stop checks the session ID; final report ID is also checked. Detected
replacement means no intentional stop/export of the replacement. The unchanged API
has a global stop operation, **not an atomic compare-and-stop**. Concurrent
administrators can race between verification and stop; use one administrative
lifecycle at a time. No stronger transactional ownership guarantee is asserted.

Both workflows default to English and support `--lang es`; HTML remains English-first
with its offline bilingual selector. Typed dictionaries include new instructions and
fixed English error codes. Existing advanced syntax, payloads, status codes, safe
no-overwrite export behavior and v1 JSON schema remain unchanged. US-1504 stays
deferred; playback is still UNOBSERVED and HTTP/score observations do not certify it.
