## Inspected boundaries and definitive categories

Inspected the TypeScript provider registry and resolver, catalog/manual/local JSON,
external HTTP and addon adapters, URL-policy and request helpers, addon manifest
parser/cache, Python coordinator and HTTP response boundary, recorder, controller,
event/report validators, private projection, export workflow and HTML renderer.
Only existing boundary evidence is classified:

| Recorded category | Existing evidence | Limits |
| --- | --- | --- |
| REGISTRY_DEADLINE | The registry's own timeout signal has expired and the existing outcome branch selects TIMED_OUT | Not a claim about an adapter's internal deadline, socket phase or network root cause |
| URL_POLICY_REJECTED | Caught value is an existing bridge-owned ExternalUrlPolicyError | No URL, reason text, DNS address or response is exported; does not imply a network request ran |
| CAUSE_UNDETERMINED | FAILED without either reliable discriminator above | Explicitly unknown, not assumed transport, timeout, malformed response or programming failure |

The same outcome precedence is retained: caller cancellation first, registry deadline
second, otherwise FAILED. CANCELLED is not a provider failure event. RETURNED_ZERO,
RETURNED_RESULTS, DISABLED and NOT_OBSERVED also emit no provider failure category.
Abandoned work remains uninvoked on retry under the existing registry rules.
Historical/truncated FAILED or TIMED_OUT without a category is labelled "Failure
category not captured", distinct from an actually observed CAUSE_UNDETERMINED.

No text/name/code/cause/stack/header/body/response inspection is used to classify
exceptions. Arbitrary errors named ExternalUrlPolicyError or TimeoutError do not
establish those causes. Prototype traps in hostile exception objects are contained
and classified unknown; their message/name/code/stack getters are not read.
Classification and the new event/callback allocation are conditional on an active
failure observer. Existing generic operational logging remains unchanged.

## Deliberately stopped deeper classification

External HTTP and addon adapters create generic Error objects for rejected HTTP
statuses, content-type/body/size/depth/schema checks and manifest validation. Native
fetch/DNS/body-reading failures and internal exceptions can also arrive as generic
errors. The existing transport/redirect boundary does not carry a closed provenance
contract to this catch. Parsing arbitrary upstream strings, Error.name or code
would conflate unrelated causes. Distinguishing transport/response/internal failure
reliably would require a new adapter/transport error-propagation contract; that
subscope is stopped and deferred, not implemented speculatively.

Python's registry does distinguish timeout, resolver_error and invalid_result
internally. Its HTTP success envelope exports streams, while configured resolver
unavailability maps to a generic non-OK response. The Node adapter consumes streams
and throws generic errors on a non-OK response; those per-resolver outcomes are not
available in this diagnostic call boundary. No Python/Kodi or HTTP protocol changes
were made. Catalog fallback errors intentionally swallowed by existing code remain
swallowed; valid empty output stays empty, never a newly inferred error. Addon
manifest cooldown/eligibility and cached exception behavior are unchanged. Startup
configuration failures outside an invoked registered provider are not retroactively
reconstructed as provider failure events.

## DTO, privacy and report behavior

A separate PROVIDER_FAILURE event has exactly kind, numeric provider slot (0..63)
and closed category. It contains no original exception or provider object. It follows
the existing PROVIDER_STATE at the same passive catch. The optional registry hook
keeps existing observer consumers compatible; callback failures cannot control
execution, concurrency, filters, timeout, results or source admission.

Technical report **v4** is selected only when the new event is captured. Later
EXCLUSION/SOURCE events cannot downgrade it. The strict updated reader accepts
V1/V2/V3/V4 and rejects PROVIDER_FAILURE in V1/V2/V3. V4 can also contain the existing
V3 exclusions. Old events are not reinterpreted and private wrapper version 1 is
unchanged. Recorder storage and JSON/HTML exports already use the common projected
model; they require no separate free-text export path. Old strict readers reject
new V4 reports and must be updated. No HTTP capability/ownership protocol changed.

The provider table has a localized category column. Technical timeline and observed
state filtering expose the same closed category, independent of candidate filters.
The report preserves the existing state, returned/delivered counts and source rows.
Private provider/title context remains opt-in; normal exports contain only provider
ordinals. More events consume the same capture limits; a truncation between FAILED
and PROVIDER_FAILURE leaves the category unobserved rather than invented.

## Funnel clarification

PROBED now has a short English/Spanish explanation: candidates reaching that
boundary are not necessarily executed HTTP probes or verified transports. An
optional breakdown totals **observed probe states**, explicitly not request counts.
It is shown only for closed resolution/report captures whose latest PROBED SNAPSHOT
has count == observed, exactly that many individual PROBED observations, and unique
candidate IDs matching that count. Zero complete observations can show zero. Missing,
duplicate, legacy count-only or truncated evidence shows breakdown unavailable.
Snapshots and candidate matrix evidence are unchanged. No transport split is inferred
from SOURCE at intake/final because that is not per-candidate transport evidence
at PROBED. Native table headings, focus/filter behavior, textContent rendering,
offline translations, default-deny/hash CSP and limits remain in place.
