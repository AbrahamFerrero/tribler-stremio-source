## Architecture

The bridge is a neutral, modular media engineering project. Catalogs describe
media; stream providers discover candidate sources; resolution normalizes,
qualifies, deduplicates and ranks them. Playback and networking have separate
responsibilities:

```text
Stremio -> local Node bridge -> catalog / StreamProviderRegistry
                                      -> StreamResolver -> PlaybackManager
                                                           |-> Direct HTTP(S)
                                                           |   -> OutboundTransport
                                                           `-> Tribler REST/stream

ExternalHttpStreamProvider -> local Python host -> disposable Kodi-compatible worker
```

Direct HTTP/HTTPS obtains bytes through the bridge's outbound URL/DNS/redirect
policy. BitTorrent is handled exclusively by Tribler; the bridge proxies its
official streaming endpoint. A Direct failure never silently starts a torrent.
Python/Kodi returns data, does not control Tribler and receives no Tribler
connection variables. Installed resolver code is trusted local code running in
a separate process, with bounded IPC and audit restrictions, not an OS sandbox.
See the [README](../../README.md) and [Python contract](../../python-adapter-host/README.md).

## Changes in v1.3

- Bounded Identity states and separate transport/identity presentation, with
  current qualification reapplied to cached results.
- Probe cache recovery before fresh network-slot allocation, preserving bounded
  scheduling, cancellation and provider turns.
- Shared HLS session inactivity, bounded child replacement and whole-tree
  revocation/eviction; conditional requests use token-scoped representation binding.
- Recipient-scoped headers, credential redirect containment, HLS text minimization
  and hardened bodyless-response handling.
- Startup-local Python resolver profiles and aggregate/discovery contracts,
  fair result aggregation and known-zero-seed hygiene.
- Strict localhost authority/context admission, independent administrative
  authentication, safer Node/Python logs/errors and Windows host environment filtering.
- Synthetic evaluation fixtures and generic tools that accept explicit external
  inputs; private corpora and real availability records are not release fixtures.

Cache-first behavior has controlled regression coverage. Its causal real-world
benefit was not isolated by A/B comparison; no percentage speedup is claimed.

## Identity and presentation

Transport verification (`Verified` in older descriptions, compact `HTTP✓` or
`HTTPS✓` in current output) means bounded media/probe evidence. It does not prove
the requested title, audiovisual correctness, sustained playback or torrent
availability. An inspected synthetic response is not real BitTorrent playback.

The bridge owns classified identity states: UNKNOWN (`ID?`), SUSPICIOUS (`ID!`),
CORROBORATED (`ID✓`) and rejected CONTRADICTION. Unclassified sources may have no
marker. Providers cannot supply authoritative confidence simply by declaring it.
Current corroboration is a bounded resource/runtime policy, not a semantic
identity certificate. Missing evidence can remain eligible; explicit supported
contradictions can reject a source. Production series metadata does not supply
exact episode duration, and MKV duration/completeness is not independently measured.

PR6 remains open and Identity frozen. At the recorded integration checkpoint,
41 provenance/composition dimensions and two dependent ranking dimensions were
explicitly deferred: 43 unmet requirements across 16 failing STRICT scenarios.
BASELINE recognizes the known inventory; it does not convert STRICT failures
into conformance. These decisions are preserved without reopening the campaign.

## Compatibility and installation

Use [Windows quick start](../../README.md#quick-start-on-windows), `npm ci`,
`.env.example` and the synthetic configuration templates. Configure local Tribler
before starting the bridge. Node's declared engine is >=20; CI is configured for
Node 20 and Python 3.11 on Linux and Windows. These are configuration facts, not
proof of an exhaustive runtime/client matrix. Python is optional; use its
[supported launcher and setup](../../python-adapter-host/README.md#start) when needed.

Install the local manifest from the README in the intended Stremio client. Standard
addon support is generic and bounded; it does not promise every Stremio release,
addon type or third-party Kodi API. Exact Origin admission can reject clients
using another context. Kodi compatibility deliberately implements a limited API
subset; HTTP requests cannot select modules, commands, callables or addon paths.

Existing operator clients must add Bearer authentication to administrative reads
and writes. Provision `BRIDGE_ADMIN_TOKEN` independently as 32 random bytes encoded
in 64 hex characters, through a local secret manager/process environment. Without
it administration is disabled. Do not reuse the Tribler key or put secrets in URLs.
The addon request timeout defaults to 5000 ms in `src/config.ts`. An 8000 ms
local recommendation is optional configuration, not the production default.
There is no need to change production configuration defaults for these notes.

## Security and trust

The bridge binds to `127.0.0.1`; Host must match the actual listener port and local
authority. `PUBLIC_BASE_URL` is restricted to the supported local HTTP root profile.
Administrative routes require the Bearer secret and refuse browser-context
headers. Discovery requires the exact Stremio Origin profile. Legacy auto/play
routes retain native playback compatibility; source/HLS routes require valid
opaque capabilities and allow wildcard CORS. See the precise
[route policy](../http-api-contracts.md#required-localhost-boundary).

Origin and native-header absence are not client identity. Local processes can
forge context headers; capability holders can replay valid tokens. Loopback is
not same-user process isolation. The release review records Desktop validation
of the implemented localhost controls and explicit acceptance of these residual
risks for v1.3 localhost-only use; this documentation pass adds no Desktop run.
Advanced localhost hardening remains deferred.

Outbound direct requests validate destinations/DNS, pin connections and revalidate
redirects. Source-header exceptions are scoped by local policy. HTTPS-labelled
sources do not silently downgrade; unsupported TLS/headers may cause failure.
Direct HTTPS does not conceal the public connecting IP from the server. Tribler
privacy depends on Tribler and the network; local observations prove no global
anonymity. R-020 remains open for broader metadata/session/legacy/log/artifact
disclosure, with bounded residual risk provisionally accepted for v1.3. See [SECURITY](../../SECURITY.md) and
[recipient privacy](../http-recipient-privacy.md).

## Limitations and publication boundary

- HLS inactivity expires shared authority; capacity pressure may evict active
  sessions. Old live-window children are revoked. A response already streaming
  bytes does not by itself renew authorization. See [lifecycle](../hls-token-lifecycle.md).
- Ambiguous multi-file episode torrents fail closed. Swarm availability and
  Tribler version/configuration affect startup and seek latency.
- Checkpoint C research is closed with PARTIAL functional evidence. Additional
  SourcePack utility and Kodi audiovisual precision remain unproven; transport
  success is not functional content acceptance. Sustained playback, seek,
  pause/resume and final client UI evidence remain separate.
- The embedded development-tool source-map vulnerability remains open under
  temporary local-integration acceptance. Zero declared npm advisories do not
  repair the bundle. See [dependency review](../dependency-security-review.md).
- Private development ancestry contains private material and must never be
  merged directly into a public main branch or exposed publicly. The independent
  public source repository starts from the approved, audited neutral snapshot
  with a separate root history; it does not inherit the private development ancestry. Keeping ignored
  files out of a working tree or squashing commits does not certify all reachable
  history and references; review the exact public files, dependencies, fixtures,
  licenses and reachable references before publication. These documents do not
  approve a manifest, publish a release or certify every document as public-safe.

Current debt and delivered mechanisms are separated in [FUTURE_WORK](../../FUTURE_WORK.md).
