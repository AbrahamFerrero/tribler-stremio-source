# Tribler Stremio Bridge v1.0.0

Historical private development checkpoint, preceding the planned first public
v1.3.0 source release. Results and limitations below belong to that checkpoint;
they do not describe a prior public release or a new validation run.

## Highlights

- Local Stremio bridge with configurable catalogs and pluggable stream providers.
- Direct HTTP/HTTPS playback alongside BitTorrent playback delegated to Tribler.
- Standard Stremio addon providers and an optional isolated local Python resolver host.
- Movie and episode resolution with deterministic file selection, fail-closed ambiguous torrents, Range/seek support and bounded Tribler read-ahead.
- Stream ranking uses direct-probe health and torrent availability while preserving the selected HTTP(S) or Tribler transport.

## Security & privacy

The service and Tribler control path are loopback-only. Direct HTTP/HTTPS uses URL, DNS and redirect validation, minimized headers and opaque temporary playback tokens. Node does not implement direct BitTorrent networking. Python resolver modules are selected only by local startup configuration.

A local runtime audit observed no non-loopback TCP during the tested Tribler playback window. This is not evidence of global network anonymity.

## Configuration

Copy `.env.example` to `.env` and use `config/*.example.json` as the basis for ignored `config/*.local.json` files. Supported providers can be configured through local environment and configuration files without editing application code.

## Validation

The release validation includes the repository safety scan, TypeScript
typecheck, ESLint, 250 non-acceptance Node tests, 7 system-acceptance tests,
production build and 54 Python tests. Coverage is informational: no percentage
threshold is a release gate. Real-local evidence is recorded separately and
does not make a universal availability or anonymity claim. Real-local Tribler
qualification observed cold metadata in about 3.1 seconds and a cold swarm
delay of about 27 seconds before Tribler emitted bytes; once pieces were
available, bridge overhead was measured in tens of milliseconds.

## Known limitations

Provider availability depends on configured third parties; `/health` returns 503 when any enabled provider is in an error state even if Tribler remains reachable. Cold torrent startup and forward seeks can be delayed by swarm availability and Tribler piece acquisition. Warm playback adds negligible bridge overhead. Ambiguous multi-file episode torrents are rejected. The Python/Kodi compatibility layer supports a deliberately limited subset, and local privacy auditing cannot prove anonymity against external observers.
