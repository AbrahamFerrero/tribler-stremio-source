## Behavior and limits

US-1511 recognizes a deliberately small structural MP4/Matroska subset within
the existing inspected prefix of at most 64 bytes. Otherwise opaque direct
sources can be admitted only with normalized `application/octet-stream`, a
verified coherent initial HTTP 206/Range, consistent observed lengths and
identity encoding. Existing deterministic security, Identity and HLS decisions
retain precedence. No new requests, read budgets or probe slots are introduced.

HTTP 200, missing/malformed or other MIME, WebM, unsupported brands/headers and
other containers gain no new admission path. Valid files outside this small
subset may still be rejected. A recognized container does not verify video
tracks, codecs, content identity, full-file integrity or sustained playback.
No universal availability, performance or playback improvement is claimed.

Minimized diagnostic `DIRECT_MEDIA_SIGNATURE` events use technical v8 only when
stored; historical v1–v7 remain readable. The private envelope remains v1 and
capture defaults and bounds are unchanged. See the [contract](../diagnostics.md).

The additional Windows Python launcher correction handles duplicate-case
environment names without changing the parent environment. The same child
allowlist applies and conflicting permitted values fail before Python starts.
This change has separate synthetic launcher coverage; original US-1511 QA alone
does not cover it.

Networking, SSRF/DNS/redirect/TLS/credential boundaries, localhost-only operation,
provider neutrality, Identity, ranking, deduplication, quotas and HLS policy remain
unchanged. PR6, R-020, Identity STRICT and post-resolution observation debts remain.
The closed exploratory smoke campaign is not a final-candidate playback PASS.
