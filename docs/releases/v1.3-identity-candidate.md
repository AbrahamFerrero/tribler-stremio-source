# Local v1.3 Identity integration candidate

Historical internal checkpoint: **2026-10-17**, preceding the v1.3 release
candidate. Results below describe that integration checkpoint, not a recent
execution or public acceptance. See [v1.3.0](v1.3.0.md) for release status.

## Scope decision — 2026-10-17

The checkpoint deferred 41 STRICT dimensions dependent on PR6,
independent provenance and confidence composition, plus two ranking dimensions
whose demonstration requires unavailable positive confidence states. These are
43 unmet requirements across 16 failing scenarios, not satisfied requirements.
The original acceptance contract, expectations and known-violation inventory
remain intact. PR6 stays open, Identity stays frozen and R-020 stays open.
Checkpoint C remains closed as research with PARTIAL functional evidence.
This decision does not grant final privacy, UI, playback or main acceptance.

## Inputs and integration boundary

The checkpoint combined the release transport/security contracts and Identity
qualification/presentation work. Its validation applies to that combined tree.

Eleven files required actual conflict resolution: the recipient privacy document,
app, automatic-stream, config, http-privacy, outbound-transport, playback manager,
direct probe, DirtyUpstream, recipient-header-policy and source-request-headers.
Each conflict was reviewed against both contracts. Keep strict startup rejection
of empty header rules, recipient authorization, HTTPS downgrade containment,
cleanup and adversarial regressions from release. Combine those with Identity's
representation binding, HTTP validation, HLS session/token lifecycle, canonical
header keys, bounded probing and bridge-owned identity states. Retain both sides'
fixture capabilities and tests. No policy relaxation or new feature is included.

## Data boundary and remaining risks

The integration checkpoint still contained a private evaluation corpus. Later
source hygiene removed it and replaced the test dependency with a synthetic
fixture. Removing a tracked file does not erase inherited Git history. A public
source repository requires a separately reviewed snapshot and independent history;
this historical integration record supplies neither publication authorization
nor evidence that inherited history is publicable.

R-020 remains broader than the bounded header, validator, redirect, playlist and
presentation protections: remaining response metadata, session/rendition fields,
legacy APIs/logs/artifacts and necessary compatibility headers/locators need their
own evidence. No anonymity or complete privacy claim is made. See
[recipient privacy](../http-recipient-privacy.md) and
[dependency risk acceptance](../dependency-security-review.md).
The temporary local-only `magicast@0.5.5` embedded `source-map-js@1.2.1` acceptance
is separate from npm audit and does not cover a public snapshot. A clean audit
does not repair or certify that bundle.

Final Stremio UI rendering/readability and sustained real playback, seek,
pause/resume and content truth remain unproven. Synthetic HTTP bytes and system
fixtures do not supply audiovisual acceptance, real provider compatibility or
SourcePack functional closure. No commercial/provider campaign was run.
